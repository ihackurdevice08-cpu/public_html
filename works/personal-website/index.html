사용 프롬프트

웹사이트 제작 프롬프트Claude Code

결과물 폴더를 지정하고 범위, 기술, 화면 구성, 디자인 기준을 함께 전달한 요청

[역할] 너는 정적 웹사이트를 만드는 프론트엔드 개발자야. 나는 한림대학교 AI 스마트 워크 수업의 결과물을 한곳에 모은 개인 포트폴리오 사이트를 만들려고 해.

[작업 폴더] 지정한 폴더 안의 주차별 결과물(보고서, 발표자료, 이미지, 데이터 분석 결과)을 확인해서 사이트에 올릴 항목으로 정리해 줘. 원본 파일은 수정하지 말고 사본으로 작업해 줘.

[제외 대상] 수업에서 제공받은 자료, 원본 데이터 파일, 영상 파일, 압축 파일, 캐시와 임시 파일은 사이트에 올리지 마.

[기술 조건]
- 순수 HTML, CSS, JavaScript로 작성
- GitHub 저장소와 연결된 Netlify 무료 플랜에 배포할 수 있게 별도 빌드 없는 정적 파일로 구성
- 항목 정보는 JSON 파일 한 곳에서 관리하고, 스크립트로 페이지를 생성
- 이미지는 WebP로 변환해 용량을 줄이기
- 검색 엔진에 노출되지 않게 설정

[화면 구성]
- 홈: 프로젝트 선택 화면. Vertical, Horizontal, Grid 세 가지 보기
- 소개: 섹션별 항목 목록
- 상세: 산출물 뷰어, 제작 의도, 제작 방향, 핵심 수치, 사용 프롬프트, 제작 순서
- 문의하기: 이메일 주소가 화면에 바로 드러나지 않게 확인 절차 추가

[디자인] 흰 배경, 검정 글자, 어두운 파랑 포인트색 하나, 맑은 고딕. 장식 없이 기본 레이아웃과 세부 디테일로 완성해 줘. 모바일에서도 깨지지 않아야 해.

[작성 규칙]
- 파일 내용에서 확인되지 않은 사실은 쓰지 말 것
- 항목 이름은 파일 이름이 아니라 담은 내용으로 지을 것
- 내가 직접 지시한 수정만 반영하고, 지시하지 않은 부분의 문제는 고치지 말고 목록으로 알려 줄 것

[출력] 전체 사이트 파일과 폴더 구조, 페이지 생성 방법
GitHub 연동 및 커밋 프롬프트Claude Code

저장소 연동 후 수정본 커밋까지 Claude Code가 수행하도록 한 요청

[역할] 너는 이 프로젝트의 버전 관리를 맡는 개발자야.

[요청] Claude Code에 내 GitHub 저장소를 연결하고, 수정이 끝난 파일을 직접 커밋해 줘. 수정할 때마다 내가 파일을 저장소에 하나씩 올리지 않아도 되게 하려는 거야.

[조건]
- 사이트 생성 스크립트의 검사를 통과한 상태에서만 커밋
- 내가 지시한 변경만 커밋하고, 지시하지 않은 파일은 건드리지 말 것
- 커밋 메시지는 무엇을 바꿨는지 알 수 있게 작성
- 저장소에 푸시하는 것은 내가 변경 내용을 확인한 뒤에 직접 진행

[출력] 커밋 목록과 변경 내용 요약

작업 순서

  1. 01GitHub 저장소 생성
  2. 02Netlify 연결: 저장소에 올린 파일이 배포되도록 설정
  3. 03작업 지시서 작성: 범위, 제외 대상, 디자인 기준, 파일 구조 확정
  4. 04결과물 폴더를 지정해 Claude Code가 파일을 점검하고 항목별로 정리
  5. 05항목 정보를 JSON 한 곳에 모으고, 페이지를 만드는 스크립트로 HTML 생성
  6. 06화면을 확인하며 내용, 디자인, 구성, 기능을 수정 요청으로 반복해서 보완
  7. 07Claude Code에 GitHub를 연동해 수정본을 직접 커밋하도록 구성
